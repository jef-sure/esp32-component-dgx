# Картинки из PNG

Программа держит свои картинки файлами PNG рядом с исходниками. Сборка
делает из каждого набора картинок файл байтов `.dgxi` и вкладывает его в
прошивку. Во время работы DGX читает картинки там, где они лежат: пиксели
остаются во flash, а в ОЗУ лежит только небольшая структура. Так же читается
и файл из файловой системы или из сети.

## Заказ

Заказ называет набор картинок, его файлы PNG и то, как их хранить. Он
пишется в `CMakeLists.txt` программы или любого компонента:

```cmake
dgx_image_need(wifi PNG art/wifi0.png art/wifi1.png art/wifi2.png BITS 1)  # три состояния значка, 1 бит
dgx_image_need(logo PNG art/logo.png BITS 16)                              # RGB565, прозрачность сохраняется
dgx_image_need(gauge PNG art/dial.png BITS 8 REDUCE DITHER)                # не больше 255 цветов, для таблицы
```

Пути считаются от того `CMakeLists.txt`, где стоит заказ. Слова заказа:

| Слово | Что делает |
| --- | --- |
| `PNG <файл>...` | картинки набора, в этом порядке |
| `BITS <n>` | 1, 4, 8, 12, 16, 18, 24 или 32 бита на пиксель, любая глубина vscreen; по умолчанию 16 |
| `INDEXED`, `PIXELS` или `MASK` | вид набора, см. ниже; 1, 4 и 8 бит — `INDEXED`, если не сказан другой, более глубокие — `PIXELS` |
| `REDUCE` | индексный набор, в котором цветов больше, чем вмещает глубина, сокращается до них; без него такой набор отвергается |
| `DITHER` | ошибка каждого пикселя расходится на соседей (Флойд — Стейнберг), на любой глубине |
| `INK DARK` или `INK LIGHT` | у 1 бита и у маски из PNG без прозрачности: чернила — тёмные пиксели или светлые; по умолчанию `LIGHT` |
| `ALPHA` | индексный набор сохраняет непрозрачность PNG в палитре, для 8-битной текстуры |
| `BACKGROUND <rrggbb>` | прозрачные места закрашиваются этим цветом, смешиваясь по непрозрачности |
| `ORIGIN <x> <y>` | точка привязки всех картинок набора; по умолчанию 0 0 |

У картинок набора одна глубина и одна палитра, а размер может быть разный:
состояния значка, кадры спрайта. Сторона картинки — до 65535 пикселей.

**Три вида.** Набор бывает одного из трёх видов, по тому, как DGX его рисует:

- `INDEXED`, 1, 4 или 8 бит — раскладка `dgx_image_t`, рисует
  `dgx_image_blit()`. Палитра хранит цвета исходника. Если цветов меньше
  2^бит, значение 0 прозрачно, а палитра даёт цвета значений с 1; если ровно
  2, 16 или 256, прозрачного нет, и палитра начинается со значения 0.
- `PIXELS`, любая глубина — раскладка vscreen, рисуется как vscreen поверх
  байтов файла. Значения — то, что держит vscreen этой глубины: яркость у 1,
  4 и 8 бит, как её даёт `dgx_screen_rgb()` (для монохромного экрана, для 16
  серых SSD1322); RGB у 12, 16, 18 и 24 бит; `0xAARRGGBB` у 32 бит, где `AA` —
  непрозрачность, как в PNG. У картинки от 1 до 24 бит, в PNG которой есть
  прозрачные места, они сохраняются рядом, плоскостью непрозрачности, по
  байту на пиксель. Картинка в 16 бит — это и `dgx_image_t`, её рисует
  `dgx_image_blit()`.
- `MASK`, 4 или 8 бит — доля покрытия одним цветом, как хранятся буквы
  мягкого шрифта; берётся из непрозрачности PNG, а у PNG без прозрачности —
  из яркости. Это значок одного цвета с мягким краем. В палитре одна запись —
  средний цвет PNG там, где маска покрывает.

**Точка привязки** — пиксель картинки, который `dgx_image_blit()` ставит в
данную точку экрана; зеркало и поворот идут вокруг него. Значку она не
нужна: 0 0 — его левый верхний угол. Кадрам спрайта нужна: у кадров разного
размера ноги стоят в одной точке, и спрайт, развернувшись, остаётся на
месте.

## Заказы в файле

Заказы можно держать отдельным файлом, по заказу на строку, теми же
словами:

```cmake
dgx_image_needs_file(images.txt)
```

```
# картинки программы
wifi PNG art/wifi0.png art/wifi1.png art/wifi2.png BITS 1
logo PNG "art/logo big.png" BITS 16 BACKGROUND 000000
needs more/images.txt
```

Пути считаются от папки файла; путь с пробелом пишется в кавычках, `#`
начинает комментарий. `needs <файл>` берёт заказы другого файла. Изменённый
файл заказов заново настраивает проект, а изменённый PNG, названный в нём,
пересобирает свой файл. Программа, которая пишет заказы сама, например
построитель dgx-ui, пишет этот файл, а `CMakeLists.txt` не трогает.

Ошибка останавливает настройку и называет файл и строку или
`CMakeLists.txt` и заказ:

```
images.txt:3: BITS 2: a picture takes 1, 4, 8, 12, 16, 18, 24 or 32 bits
images.txt:5: /path/art/off.png does not exist
CMakeLists.txt: dgx_image_need(logo): INK at 16 bits: ink says which pixels are 1, at 1 bit
```

## Как нарисовать

Каждый набор вложен как `dgx_asset_<имя>`, его длина —
`dgx_asset_<имя>_size`, объявлены они в `dgx_assets.h`, а читаются через
`dgx_image_file.h`:

```c
#include "dgx_assets.h"
#include "dgx_image_file.h"

dgx_image_file_t file;
dgx_image_file_open(dgx_asset_wifi, dgx_asset_wifi_size, &file);
```

`dgx_image_file_open()` проверяет весь файл и сообщает его глубину, вид,
число картинок и палитру. Ничего не копируется и не выделяется: `file`
лежит там, где его держит программа, а картинки читаются из вложенных
байтов.

**Индексная картинка** — это `dgx_image_t`. Значок в 1 бит ложится на любой
экран одним цветом:

```c
dgx_image_t icon;
dgx_image_file_image(&file, state, &icon);   /* state: 0, 1 или 2 */
dgx_image_blit(lcd, 10, 10, &icon, &(dgx_image_blit_t){.color = DGX_WHITE(dgx_rgb_to_16)});
```

Набор в 4 или 8 бит рисуется в 8-битный vscreen через карту: значение
картинки — номер цвета в таблице этого экрана. Палитра файла даёт цвета
значений, по 4 байта: R, G, B и непрозрачность; `file.first` — значение
первой записи:

```c
uint8_t map[255];
for (unsigned i = 0; i < file.colors; ++i) {
    const uint8_t *c = file.palette + 4 * i;
    map[file.first + i - 1] = nearest_index_of_my_table(c[0], c[1], c[2]);  /* map[p - 1] — номер для значения p */
}
dgx_image_blit(frame, x, y, &picture, &(dgx_image_blit_t){.map = map});
```

У картинки с полной палитрой, 2, 16 или 256 цветов, прозрачного значения
нет: её рисуют с `DGX_IMAGE_OPAQUE`, а `bg` — номер цвета записи 0.
8-битная индексная картинка — это и текстура `dgx_draw_texture_quad_with()`:
8-битный vscreen поверх `picture.pixels`, с `lut` и непрозрачностями палитры
в `alpha`.

**Картинка пикселей** рисуется как vscreen поверх своих байтов, а её
плоскость непрозрачности — это `alpha_map` квада текстуры:

```c
dgx_image_file_picture_t p;
dgx_image_file_picture(&file, 0, &p);
dgx_screen_t *logo = dgx_vscreen_from_array((void *)p.pixels, p.width, p.height, file.bits, DgxScreenRGB);
dgx_vscreen_to_screen(lcd, 10, 10, logo, 0);                 /* непрозрачно */
dgx_screen_t *opacity = p.alpha ? dgx_vscreen_from_array((void *)p.alpha, p.width, p.height, 8, DgxScreenRGB) : NULL;
/* или мягко поверх того, что под ней: dgx_draw_texture_quad_with() с .texture = logo, .alpha_map = opacity */
```

Такой экран только читают: рисовать на нём нельзя. Картинка в 16 бит — это
и `dgx_image_t` с плоскостью в `alpha`, она рисуется `dgx_image_blit()` с
поворотами, масштабом и обрезкой, см. ниже.

### Мягкий край

`dgx_image_blit()` с `DGX_IMAGE_SOFT` смешивает край картинки по
непрозрачности каждого пикселя, как мягкий текст смешивает буквы:

```c
/* маска: мягкий значок любого цвета, коробка пишется целиком поверх бумаги, поэтому не мигает */
dgx_image_file_image(&wifis, state, &icon);
dgx_image_blit(lcd, 10, 10, &icon, &(dgx_image_blit_t){
    .flags = DGX_IMAGE_SILHOUETTE | DGX_IMAGE_SOFT | DGX_IMAGE_OPAQUE, .color = white, .bg = back});

/* индексная картинка с непрозрачностью в палитре (ALPHA): через цвета файла */
uint32_t colors[256];
uint8_t  opacity[256];
dgx_image_file_colors(&arrows, lcd, colors, opacity);
dgx_image_blit(lcd, x, y, &arrow, &(dgx_image_blit_t){
    .flags = DGX_IMAGE_SOFT | DGX_IMAGE_OPAQUE, .colors = colors, .alpha = opacity, .bg = back});

/* картинка в 16 бит с плоскостью непрозрачности, поверх того, что под ней */
dgx_image_blit(frame, x, y, &ball, &(dgx_image_blit_t){.flags = DGX_IMAGE_SOFT});
```

С чем смешивается частично покрытый пиксель:

- с тем, что под ним, на экране, который читается: vscreen от 4 до 24 бит,
  дисплей на MIPI-DSI;
- с `bg` при `DGX_IMAGE_OPAQUE`, на любом экране: коробка картинки пишется
  целиком, каждый пиксель один раз, так что мягкий значок, нарисованный
  поверх себя на дисплее за шиной, не мигает;
- ни с чем на дисплее за шиной без `DGX_IMAGE_OPAQUE`: его нельзя прочесть,
  и пиксель ставится целиком, если непрозрачность не меньше половины. Дисплей
  DGX обратно не читает.

Без `DGX_IMAGE_SOFT` картинка в 16 бит или нарисованная через `colors`
ставит целиком каждый пиксель непрозрачностью от 128, остальные пропускает.
`colors` даёт индексной картинке любой экран, а не только 8-битный vscreen
через карту, и `dgx_image_file_colors()` заполняет его палитрой файла,
переведённой в цвета экрана.

**Шрифты тоже.** С `dgx_fonts_files()` каждый файл шрифта программы
вкладывается так же, под именем своего файла, и `dgx_font_file_load()`
читает его на месте:

```c
size_t need;
dgx_font_file_memory(dgx_asset_TerminusTTFMedium12, dgx_asset_TerminusTTFMedium12_size, &need);  /* 40 байт */
```

## Цвета

Одно правило для любой глубины, в две ветки.

- **Индексные.** Цвета сохраняются точно, если помещаются: в 2^бит − 1
  записей, если в наборе есть прозрачные пиксели, и в 2^бит, если нет.
  Набор без прозрачных пикселей, которому хватает меньше 2^бит цветов, тоже
  получает значения с 1 и рисуется без `DGX_IMAGE_OPAQUE`. Набор, где цветов
  больше, отвергается с их числом:
  `37 colors, 4 bits hold 15 with transparency: REDUCE, or fewer colors in
  the picture`. С `REDUCE` они сокращаются медианным сечением до того числа,
  что помещается. Пиксель с непрозрачностью меньше 128 прозрачен, остальные
  непрозрачны: `dgx_image_blit()` не смешивает. С `ALPHA` непрозрачность
  уходит в палитру, и цвета разной непрозрачности — разные записи.
- **1 бит.** В наборе с прозрачными пикселями единицы — непрозрачные
  пиксели, их цвет — средний из их цветов. В наборе без них единицы —
  светлые пиксели, от среднего серого, как считает `dgx_screen_rgb()`, или
  тёмные с `INK DARK`; две записи палитры — средние цвета нулей и единиц.
- **Маска.** Непрозрачность PNG или, если в наборе нет прозрачного, его
  яркость (чернила — светлое, или тёмное с `INK DARK`), округлённая до
  ближайшего из 16 или 256 уровней; `DITHER` раскладывает ошибку.
- **Пиксели.** Каждый цвет округляется до ближайшего цвета глубины; отказа
  нет. Яркость у 1, 4 и 8 бит — `(77 r + 150 g + 29 b) / 256`, как её берёт
  `dgx_screen_rgb()`.
- **`DITHER`** раскладывает ошибку каждого пикселя на соседей на любой
  глубине и у любого вида: ошибку округления или выбора записи.

Цвета PNG берутся такими, какими записаны: его гамма и цветовой профиль не
применяются, как их не применяет и большинство программ. PNG с 16 битами на
канал округляется до 8.

## Что делает сборка

В конце настройки одно правило делает все заказы писателем DGX,
`tools/dgx_images.py`, в `build/dgx_images/`:

- `<имя>.dgxi` каждого заказа;
- `dgx_images-files.txt`, по строке `<имя> <файл>` на заказ: по нему другая
  программа находит файл заказа.

Они делаются заново, когда меняется PNG, заказ или писатель. Второе правило
пишет `build/dgx_assets/dgx_assets.S` и `dgx_assets.h`: они вкладывают через
`.incbin` каждый файл картинок, а с `dgx_fonts_files()` и каждый файл
шрифта. Каждый файл лежит на адресе, кратном 4, и в своём разделе, который
линковщик выбрасывает, если программа его не называет.

Адрес, кратный 4, даёт сама сборка, на любой версии ESP-IDF. Внутри файла
каждая таблица и пиксели каждой картинки тоже начинаются со смещения,
кратного 4, так что 16-битные пиксели всегда выровнены, как нужно кваду
текстуры, который читает их 16-битными словами. `EMBED_FILES` ESP-IDF не
выравнивает вложенное ни в одной версии, а `target_add_binary_data(... ALIGN
4)` появился только в ESP-IDF 6.0.3 и 6.1.1: вложенный так файл может лечь по
нечётному адресу, и `dgx_draw_texture_quad_with()` откажет там 16-битной
текстуре. Картинки вкладывайте заказами.

## Файл не из прошивки

Файл из файловой системы или из сети читается так же, из буфера
`malloc()`, который выровнен:

```c
uint8_t *bytes = malloc(length);
/* ... прочесть в него length байт ... */
dgx_image_file_t file;
if (dgx_image_file_open(bytes, length, &file) == ESP_OK) { /* ... картинки, пока жив bytes ... */ }
```

Каждое смещение и каждая длина файла сверяются с его границами до того, как
файл отдан, так что порченый или обрезанный файл отвергается с
`ESP_ERR_INVALID_ARG` и описанием ошибки в журнале и никогда не читается за
концом. Файл формата более нового DGX отвергается с
`ESP_ERR_INVALID_VERSION`. Числа файла читаются побайтно, поэтому файл
читается на процессоре с любым порядком байтов.

## Писатель вручную

`tools/dgx_images.py` нужен только Python 3.8 или новее со своей
библиотекой; ESP-IDF его приносит. На командной строке он делает один файл
словами заказа:

```sh
python tools/dgx_images.py make logo.dgxi PNG art/logo.png BITS 16
python tools/dgx_images.py build images.txt out/      # все заказы файла, для сборки на компьютере
```

Программа, у которой файлы PNG свои, например сервер построителя dgx-ui,
берёт тот же писатель как модуль:

```python
from dgx_images import make, DgxiError
data = make(["on.png", "off.png"], bits=1)          # пути или байты каждого PNG
```

Отказ — `DgxiError` с теми же словами, что печатает сборка. Писатель не
читает ничего, кроме данных ему файлов PNG.

## Формат

Числа — little-endian; пиксели лежат так, как их читает вызов, который их
рисует, старший байт пикселя первым.

| Смещение | Байт | Поле |
| --- | --- | --- |
| 0 | 4 | `DGXI` |
| 4 | 2 | версия формата: 1, или 2 у маски — DGX до 0.12.11 отвергает её как более новый формат |
| 6 | 1 | бит на пиксель |
| 7 | 1 | вид: 1 — индексный, 2 — пиксели, 3 — маска |
| 8 | 2 | картинок |
| 10 | 2 | записей палитры: от 1 до 2^бит у индексного набора, 1 у маски, 0 у пикселей |
| 12 | 4 | длина файла |
| 16 | 4 | начало таблицы картинок |
| 20 | 4 | начало палитры, 0 — её нет |
| 24 | 4 | начало описания, 0 — его нет |
| 28 | 4 | длина описания |
| 32 | 32 | нули, запас |

Картинка в таблице — 16 байт: ширина и высота по 2; точка привязки, x и y
со знаком, по 2; начало пикселей и начало плоскости непрозрачности, 0 — её
нет, по 4. Запись палитры — R, G, B и непрозрачность. Описание — текст UTF-8,
строки `ключ: значение`: имя заказа, файлы PNG и автор, права и описание,
которые несёт PNG. Тот же формат описан в
[src/vscreen/image_file.c](../src/vscreen/image_file.c), в чтении, а
`make -C test/images` проверяет писатель и чтение вместе, в том числе на
тестовых картинках PngSuite.
